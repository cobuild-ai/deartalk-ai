## 📝 AI Insight (#from-ai)
- 모바일 음성 인식(STT)과 온디바이스 LLM을 결합할 때, 오디오 하드웨어의 생명주기(Microphone Driver & AudioRecord Lock) 관리가 핵심 사용자 경험을 자유해옴을 확인했습니다. 인스턴스를 빈번히 재생성하기보다 단일 인스턴스를 유지하며 세션을 재사용하는 것이 레이스 컨디션을 방지하는 최적의 패턴입니다.
- 음성 입력 기반 키보드에서는 글자 단위 삭제뿐만 아니라 '발화 호흡'에 맞춘 **문장 단위 삭제(Sentence Backspace)** 기능이 사용자 피로도를 획기적으로 낮추는 결정적인 UX 요소입니다.
- 100% 온디바이스 신경망 추론은 개인정보 보호와 네트워크 독립성을 완벽히 보장하며 실사용 가능한 훌륭한 응답 속도를 보여주었습니다.
- **브랜딩의 가치 지향성 전환:** 'GemBoard'라는 하드웨어/기술 중심(Gemma + Keyboard) 브랜드에서 'DearTalkAI'라는 사용자 가치(정중한 소통 + AI) 중심 브랜드로의 전향은 키보드 폼팩터의 물리적 한계를 벗어나 iOS/macOS 등 이종 플랫폼 확장성 측면에서 강력한 모멘텀이 될 수 있습니다.
- **온디바이스 AI 앱의 Monorepo 필요성:** 각 플랫폼(Android, Apple 등)이 개별 Repository를 사용할 경우, 온디바이스 LLM에 주입할 프롬프트 템플릿과 정제 규칙 등의 핵심 AI 자산이 파편화될 위험이 큽니다. 단일 Monorepo 구조에서 공통 Core(`shared`)와 프롬프트 템플릿을 중앙 제어함으로써, 모든 플랫폼에서 균일한 성능과 톤앤매너를 유지하는 지향점이 가장 정교하고 효율적입니다.
- **플랫폼별 UX 차이와 브랜딩의 정합성:** iOS 서드파티 키보드 앱의 마이크 접근 권한 제약으로 인해 iOS/macOS에서는 음성(STT) 중심이 아닌 **입력 텍스트 실시간 검출 및 Diff 기반 교정 UI**가 메인 기능이 되어야 합니다. 이처럼 플랫폼마다 입력 방식이 STT(음성)와 Typing(텍스트)으로 이원화되더라도, `DearTalkAI`('조심스러운 대화')라는 이름은 '대화의 톤 조절'이라는 본질적 목적을 그대로 내포하고 있으므로 두 가지 다른 UX 형태를 모두 자연스럽게 아우를 수 있는 최고의 브랜드 명칭이자 저장소명입니다.
- **역순 도메인 패키징 관례(Reverse Domain Name Notation):** Android 및 Apple 개발 시 패키지 식별자는 소유한 인터넷 도메인의 역순으로 선언하는 것이 글로벌 표준 프로토콜입니다. `deartalk.ai` 도메인을 소유할 경우 베이스 패키지명은 `ai.deartalk`로 설정되어야 하며, 안드로이드 모듈은 최종적으로 `ai.deartalk.android` 또는 `ai.deartalk.app`과 같은 형태로 정의되어 플랫폼 구조와 인터넷 도메인 간의 일치를 이끌어내야 합니다.
- **AI 어시스턴트의 통합 맥락 이해와 Workspace 설계:** AI 기반 페어 프로그래밍을 진행할 때, 특정 앱 모듈(예: `deartalk-android`) 단위로 워크스페이스를 오픈하면 타 모듈과의 결합 관계나 `deartalk-shared`에 규정된 핵심 AI 규칙을 인지하지 못합니다. 전체 Monorepo 루트(`deartalk-ai`)를 워크스페이스로 제공하여 AI에게 통합적인 문맥(Cross-Platform Context)을 부여하는 것이 개발 정확도를 극대화하는 열쇠입니다.
- **애플리케이션 ID 변경에 따른 기존 패키지 갱신**: Android OS는 패키지명(Application ID)을 기준으로 앱을 식별하므로, 패키지명이 변경되면 기존 앱의 덮어쓰기 업데이트가 불가능하고 아예 새로운 앱으로 인식됩니다. 구 버전과의 서명 권한이나 Content Provider 권한 충돌 문제를 완벽히 회피하기 위해서는 기존 단말에 설치되어 있던 구 버전 앱(`com.gemboard.ai`)을 완전히 언인스턴스(삭제)하고 새 빌드 패키지(`ai.deartalk.android`)를 단독으로 신규 배포해야 함을 기록합니다.
